### STUDENT FEATURES

#### S1: Socratic Tutor
**Novelty:** Not on any Indian platform. No Western platform has applied this to JEE/NEET.  
**Token budget:** ~400 tokens/session (3 exchanges × ~130 tokens each)  
**Model:** `llama-3.1-8b-instant` — fast enough to feel responsive; quality is adequate for guiding questions  
**How it minimises tokens:**
- System prompt is reused (cached) across all sessions
- Each exchange is short — a question, not an essay
- AI never generates the full solution (saves 300–500 tokens per session vs. giving the answer)
- Hard cap: `max_tokens: 150` per response

**System prompt strategy:**
```
You are a Socratic tutor. Never give the answer directly. Ask exactly ONE guiding question per response that leads the student one step closer to discovering the answer themselves. Keep every response under 80 words.
```

**MoSCoW:** Must Have  
**RICE:**
- Reach: 5,000 users/quarter (high — exam prep is universal)
- Impact: 4/5 (directly tests core hypothesis)
- Confidence: 90% (proven pedagogy)
- Effort: M (2 weeks)
- **RICE Score: 90**

---

#### S2: Mistake DNA
**Novelty:** No Indian platform does AI-generated qualitative error pattern analysis.  
**Token budget:** ~300 tokens/week per user (one summary call, not per question)  
**Model:** `llama-3.1-8b-instant`  
**How it minimises tokens:**
- Categorisation (conceptual / calculation / reading / formula) is done by DB logic (SQL pattern matching), NOT AI
- AI only generates the final summary paragraph (~200 words)
- Runs as an async weekly batch job, not real-time
- Prompt: "Given these error categories and counts: [JSON], write a 100-word personalised insight for the student."

**DB schema required:**
- `practice_attempts`: question_id, user_id, is_correct, error_type, subject, chapter, timestamp
- Error type is tagged at question creation time by the content team (not AI)

**MoSCoW:** Must Have  
**RICE Score: 72**

---

#### S3: Concept Graph
**Novelty:** No platform maps prerequisite concepts with AI guidance.  
**Token budget:** ~150 tokens per call (minimal — just 1–2 sentences of recommendation)  
**Model:** `llama-3.2-3b-preview` — trivially simple task; smallest model is sufficient  
**How it minimises tokens:**
- Knowledge graph is a static DB table (concept → prerequisites). Built once, never re-generated by AI.
- AI's only job: "Student is weak at [X]. Here are 3 prerequisite concepts: [A, B, C]. Write one sentence explaining which to study first and why."
- Prompt input: ~50 tokens. Output: ~100 tokens. Total: 150 tokens per call.

**DB schema required:**
- `concept_graph`: concept_id, concept_name, exam, subject, prerequisite_ids[] (array)
- `user_concept_mastery`: user_id, concept_id, mastery_score (0–100)

**MoSCoW:** Should Have (Month 3)  
**RICE Score: 54**

---

#### S4: PYQ Pattern Predictor
**Novelty:** No platform does AI probability analysis of past paper patterns.  
**Token budget:** ~800 tokens per exam per season (batch job, runs quarterly, results cached for all users)  
**Model:** `llama-3.3-70b-versatile` — pattern reasoning needs the 70B model; acceptable because it runs rarely  
**How it minimises tokens:**
- Runs ONCE per exam season (before JEE/NEET date)
- Results cached in DB as static text
- All users see the same cached output — zero per-user AI calls
- Input: CSV summary of chapter appearances across 15 years (not the papers themselves). ~400 tokens input.
- Output: Ranked list with probability scores. ~400 tokens output.

**Data requirement:** Must curate 10–15 years of JEE/NEET/UPSC papers. This is the defensible moat.  
**PYQ data sources:** NTA official archives (free), coaching institute compilations, community uploads

**MoSCoW:** Should Have (Month 2–3)  
**RICE Score: 60**

---

#### S5: Exam Psychology Coach
**Novelty:** ZERO Indian EdTech platforms address exam mental health with AI.  
**Token budget:** ~100 tokens per daily check-in — the most token-efficient feature on the platform  
**Model:** `llama-3.2-3b-preview` — 50-word output, simplest model works  
**How it minimises tokens:**
- Daily check-in is 2 questions (stress level 1–10, what happened today)
- AI output is exactly 50 words: one actionable mental tip + one affirmation
- System prompt is heavily templated; AI fills in context-specific advice
- Hard cap: `max_tokens: 80`

**Prompt template:**
```
Student has exam in [N] days. Today's stress: [X]/10. Issue: [USER_INPUT max 50 chars].
Give one practical mental tip for tonight and one sentence of honest encouragement. Max 60 words total.
```

**MoSCoW:** Should Have (Month 3)  
**RICE Score: 48**

### FOUNDER FEATURES

#### F1: India Stack Navigator
**Novelty:** No AI product does India regulatory compliance for founders.  
**Token budget:** ~500 tokens per call  
**Model:** `llama-3.1-8b-instant`  
**How it minimises tokens:**
- All compliance rules are stored in a structured DB table (rule → condition → deadline → portal)
- DB query fetches the right rules based on founder's inputs (company type, revenue, FEMA status)
- AI only formats the output into natural language and adds brief explanations
- Prompt: "Here are the applicable rules for this founder: [JSON]. Format as a friendly numbered checklist with one sentence of explanation per item."
- Input: ~200 tokens (the rule JSON). Output: ~300 tokens.

**DB schema:**
- `compliance_rules`: rule_id, trigger_condition (company_type, revenue_range, has_foreign_investment), rule_name, deadline_logic, cost_estimate, portal_url, last_updated

**MoSCoW:** Must Have (Founder section launch)  
**RICE Score: 80**

#### F2: Bharat Pricing Engine
**Novelty:** No India-specific pricing AI exists.  
**Token budget:** ~600 tokens per call  
**Model:** `gemma2-9b-it` — structured analysis and tabular output; Gemma 2 9B is better than LLaMA 8B for formatted output  
**How it minimises tokens:**
- Input: 5 structured fields (product type, target tier, B2C/B2B, monthly ARPU goal, competitor names)
- Total input: ~150 tokens
- Output: 3 pricing tiers with rationale, each ~100 words
- No document upload, no long context

**India-specific knowledge to bake into system prompt:**
- India income distribution (top 10% = ₹50K+/month, median = ₹15K/month)
- Jio effect: users expect free tier, convert on value demonstration
- GST implications: price shown must factor in 18% GST for SaaS
- B2B India: annual contracts preferred over monthly for trust
- Tier 2/3 pricing: 40–60% lower than Mumbai/Bangalore pricing for same product

**MoSCoW:** Must Have (Founder section launch)  
**RICE Score: 72**

#### F3: Investor Match
**Novelty:** No AI-matched Indian investor database exists publicly.  
**Token budget:** ~200 tokens per call  
**Model:** `llama-3.2-3b-preview` — matching + brief explanation, tiny model sufficient  
**How it minimises tokens:**
- Matching is done by DB query (SQL filter by sector + stage + cheque size) — zero AI
- AI only writes 1-sentence explanations for why each matched investor is relevant
- Input: ~50 tokens (founder brief). Output: ~150 tokens (10 matches × 1 sentence each)

**DB schema:**
- `investors`: investor_id, name, firm, sectors[], stages[], min_cheque_inr, max_cheque_inr, geography, portfolio[], notes, last_updated
- Data curation: Manual initial build from public sources (LinkedIn, Crunchbase, AngelList India, media reports)
- Start with 200 investors. Grow to 500 by Month 6.

**MoSCoW:** Should Have  
**RICE Score: 65**

#### F4: Pitch Roast
**Novelty:** India-investor-lens feedback doesn't exist as an AI product.  
**Token budget:** ~1,200 tokens per roast — highest of all features, but infrequent  
**Model:** `llama-3.3-70b-versatile` — nuanced judgment needs the 70B; acceptable because it runs max once/week per user  
**How it minimises tokens:**
- User pastes pitch TEXT (not uploads a file) — removes PDF parsing cost
- Input is capped at 500 words (hard limit enforced in UI with word count)
- Output: structured feedback in 5 sections (problem, market, solution, team, ask)
- Runs async — user submits, gets result in 60 seconds (async queue, no blocking)
- Rate limit: max 3 roasts per user per month (prevents abuse)

**System prompt persona:**
```
You are an experienced Indian angel investor who has reviewed 500+ pitches. You funded 15 startups.
You give specific, honest feedback. You understand India-specific issues: CAC/LTV for Indian markets,
GST compliance, RBI regulations, India-first traction requirements, realistic India valuations.
You don't sugarcoat. You end each section with one specific action the founder can take.
```

**MoSCoW:** Should Have  
**RICE Score: 58**

#### F5: 0 to GST
**Novelty:** No platform gives a personalised India startup launch roadmap.  
**Token budget:** ~600 tokens per call  
**Model:** `llama-3.1-8b-instant`  
**How it minimises tokens:**
- Template-heavy: AI fills blanks in a 7-day framework (Day 1: X, Day 2: Y…)
- Input: 3 fields (business type, estimated first-year revenue, target market)
- Output: 7-day checklist, each day has 1–3 tasks with specific URLs and cost estimates
- Most content is template; AI personalises language and adjusts for business type

**MoSCoW:** Must Have (Founder section launch)  
**RICE Score: 70**

## Groq Key Rotation Architecture

### Problem
- Each Groq free account: ~6,000 requests/day, ~500,000 tokens/day (estimated)
- 3 accounts total: ~18,000 req/day, ~1,500,000 tokens/day
- At scale this supports ~1,800 active users (10 req/day each)

### Architecture

```
User Request
     │
     ▼
Next.js API Route (/api/ai/query)
     │
     ▼
Edge Middleware: Auth check + Rate limit (user max 10 req/day)
[Upstash Redis: user:{id}:daily_calls → increment, expire at midnight]
     │
     ▼
Key Selector (Upstash Redis lookup)
     │
     ├─ Fetch groq:key:0:req_today, groq:key:1:req_today, groq:key:2:req_today
     ├─ Filter: req_today < 5,500 (buffer below 6,000 limit)
     ├─ Select: lowest req_today (least-used key first)
     └─ If all exhausted: return HTTP 429 {"error": "AI busy, try in a few hours"}
     │
     ▼
Groq API call (selected key)
     │
     ├─ On success: increment groq:key:{n}:req_today in Redis
     ├─ Store response in cache: cache:prompt:{hash} → response (TTL: 86400s)
     └─ On rate limit error (429 from Groq): mark key as "cooling" for 60s, retry with next key
     │
     ▼
Return response to user
```

### Redis Keys

```
# Per-key daily tracking (reset at midnight UTC)
groq:key:0:req_today      → integer, expires at midnight UTC
groq:key:0:tokens_today   → integer, expires at midnight UTC
groq:key:1:req_today      → integer
groq:key:1:tokens_today   → integer
groq:key:2:req_today      → integer
groq:key:2:tokens_today   → integer

# Per-user daily rate limit
user:{userId}:daily_calls → integer, expires at midnight UTC

# Response cache (reduces Groq calls by 20-40% for repeat questions)
cache:prompt:{sha256(model+prompt)} → response string, TTL 86400s

# Key cooling (when a key hits rate limit mid-day)
groq:key:0:cooling        → "1", TTL 60s
```

### Emergency Fallback

If all 3 keys are exhausted AND the cache doesn't have a hit:
1. Queue the request with a 30-second delay
2. Show user: "One moment — we're handling high demand. Your answer is coming."
3. After 30 seconds, retry key selection
4. If still all exhausted: "AI is busy right now. Try again in a few hours. Your question is saved."

### Caching Strategy (Reduces Groq Load 20–40%)

- Cache key: SHA256 of (model_id + system_prompt + user_message)
- Cache TTL: 24 hours for most features; 7 days for PYQ Predictor (changes quarterly)
- This means if 100 students ask the same JEE question, Groq is called once

## Model Selection Guide

| Feature | Model | Why |
|---------|-------|-----|
| Socratic Tutor | `llama-3.1-8b-instant` | Fast (feels responsive), quality adequate for guiding questions |
| Mistake DNA | `llama-3.1-8b-instant` | Simple summary task; 8B is more than enough |
| Concept Graph | `llama-3.2-3b-preview` | 1-sentence output; smallest model works |
| PYQ Predictor | `llama-3.3-70b-versatile` | Pattern reasoning; runs quarterly, worth the quality |
| Exam Psychology | `llama-3.2-3b-preview` | 50-word output; 3B is perfectly sufficient |
| India Stack Navigator | `llama-3.1-8b-instant` | Formatting task; 8B handles structured output well |
| Bharat Pricing Engine | `gemma2-9b-it` | Better structured/tabular output than LLaMA 8B |
| Investor Match | `llama-3.2-3b-preview` | 10 × 1-sentence outputs; tiny model is fine |
| Pitch Roast | `llama-3.3-70b-versatile` | Nuanced investor judgment; run infrequently |
| 0 to GST | `llama-3.1-8b-instant` | Template-filling task; 8B is fast and sufficient |

## Flags

**Red Flags:**
- Pitch Roast uses 1,200 tokens — highest cost feature. Must rate-limit aggressively (3/month/user).

**Yellow Flags:**
- `llama-3.2-3b-preview` is a preview model — may be deprecated. Have `llama-3.1-8b-instant` as fallback for all 3B tasks.
- Investor DB requires ongoing curation. Build a simple admin page to add/update investor records.
